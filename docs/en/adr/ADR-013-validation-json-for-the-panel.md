# ADR-013: validation.json in data/public/ for the validation panel

- **Status**: Proposed
- **Date**: 2026-11-14
- **Decided by**: to be confirmed by the team (proposal from issue #39)

## Context
The validation panel (C3-06, #39) shows the numbers of the web app next to those of JPL Horizons. The reference values live in `tests/reference/horizons_reference.csv` and `tests/reference/raw/`. The web app cannot read `tests/`: Vite serves only `data/public/` (`publicDir` in `web/vite.config.js`), and an import from outside `web/` fails in dev and in the Vercel build. The contract (ADR-002) says that Python and the web app talk to each other only through JSON in `data/public/`.

## Decision
A new file is added to the contract: `data/public/validation.json`, generated by `scripts/make_validation_json.py` from `tests/reference/`. It contains the tolerance (0.1°, ADR-005), the source and the reference rows (site, body, UTC instant, azimuth, elevation). Schema: `data/schema/validation.schema.json`. Nothing new is calculated: saved Horizons answers are only copied.

## Rejected alternatives
- **Importing the CSV directly in Vite (`?raw`)**: it does not touch the contract, but the web app reads a file from `tests/` and depends on the Vite configuration outside `web/`.
- **Duplicating the values by hand in the web code**: it drifts out of sync with `tests/` without warning.

## Consequences
- The contract gets one more file. `tests/test_contract.py` validates it against the schema.
- If Horizons changes and `tests/reference/` is regenerated, the script has to be run again and `data/public/validation.json` committed.
- Dates outside the range of the web app (after 2027-12-31, `DATA_END_MS`) are shown as "out of range" and do not count as an error.
