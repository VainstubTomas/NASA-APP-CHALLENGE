# ADR-007: Commit format, Git hooks and unprotected `dev`

- **Status**: Accepted
- **Date**: 2026-11-13
- **Decided by**: full team
- **Partly replaces**: ADR-003 (commit rules and protection of `dev`)

## Context
The branch `chore/git-hooks` added hooks (`.githooks/`) stricter than what was documented in ADR-003, `CLAUDE.md` and `docs/04-GIT-WORKFLOW.md`: mandatory scope, fixed format, English messages, a minimum of 10 words and commit blocking only on `main`. The documentation said something else, and `dev` was listed as protected without the hook covering it.

## Decision
- **Format**: not enforced. `type(scope): description` is suggested (types `feat`, `fix`, `docs`, `test`, `chore`), but the hook accepts any first line so the messages generated by the AI-powered IDE can be used.
- **Language**: by convention commit messages are in English (the hook does not check it); the rest of the documentation was kept in Spanish at the time of this decision.
- **Length (the only rule validated)**: minimum 10 words in the first line, even for small commits.
- **Suggested scopes**: `web`, `ephemeris`, `terrain`, `data`, `tests`, `docs`, `scripts`. They are only suggestions.
- **Hooks**: activated once per clone with `git config core.hooksPath .githooks`; `--no-verify` skips them (emergencies only).
- **Squash merge**: the recommended method, but not forced (all three stay allowed). GitHub does not run `commit-msg` on a squash, so the PR title must also have 10 words or more.
- **`dev` unprotected**: only `main` is protected (hook and GitHub rule). `dev` is the team's sandbox; everything still enters via PR by convention.

## Discarded alternatives
- Protecting `dev` too with the hook: friction without benefit, because the flow already forces working on branches and entering via PR.
- Requiring the `type(scope)` format: discarded because it blocks the IDE's auto-generated messages, which are useful.
- Spanish commit messages: English was preferred as the standard of the tool and the history.
- A lower minimum word count: 10 is reasonable and forces explaining what and why.

## Consequences
- Hooks must be activated in every new clone; it is in the checklist of `docs/en/04-GIT-WORKFLOW.md`.
- A direct commit to `dev` is not blocked: it depends on respecting the convention.
- PR titles are reviewed by hand, because no hook validates them.
